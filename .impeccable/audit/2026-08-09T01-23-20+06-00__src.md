## Detailed Findings by Severity

### [P1] Small-text hierarchy falls below WCAG AA

- **Location:** `src/theme/tokens.css` (`--text-dim`, `--text-faint`, `--text-fainter`, `--text-label`) and their consumers.
- **Category:** Accessibility / Theming
- **Impact:** Sidebar section names, metadata, empty-state details, and secondary instructions are difficult to read, especially at the app's compact 10–12px sizes.
- **Evidence:** Against `--bg-sidebar` the tokens measure approximately 4.00:1, 3.15:1, 2.65:1, and 2.23:1 respectively; rendered scans reproduced the 2.23:1 sidebar labels across every destination.
- **WCAG:** 1.4.3 Contrast (Minimum)
- **Recommendation:** Raise semantic secondary-text tokens to at least 4.5:1 on card/elevated surfaces; preserve hierarchy with weight, size, and spacing rather than illegibility.
- **Suggested command:** `$impeccable colorize`

### [P1] Core selection cards are pointer-only

- **Location:** `src/screens/Download.tsx` source-video cards; `src/features/thumbnail-editor/LayersPanel.tsx` saved-template cards and delete affordance.
- **Category:** Accessibility / Implementation Integrity
- **Impact:** Keyboard users cannot select the source video that starts production or apply/delete a saved thumbnail template.
- **Evidence:** These are visible `<div onClick>` surfaces without `tabIndex`, keyboard activation, or pressed state. This also violates the repository design-system rule that actions are buttons.
- **WCAG:** 2.1.1 Keyboard; 4.1.2 Name, Role, Value
- **Recommendation:** Use semantic buttons where nesting permits; otherwise supply button role, focusability, Enter/Space activation, accessible names, and selected state.
- **Suggested command:** `$impeccable harden`

### [P2] The shell has no navigation or main landmarks

- **Location:** `src/app.tsx`, `src/components/Sidebar.tsx`, `src/screens/RenderQueue.tsx`.
- **Category:** Accessibility / Implementation Integrity
- **Impact:** Assistive-technology users cannot jump to primary navigation/content, and Render Queue is the only destination without a semantic page heading.
- **Evidence:** Browser DOM reported zero `main`, `navigation`, and banner landmarks; 10 destinations expose an `<h1>`, while Render Queue uses a styled `<div>`.
- **WCAG:** 1.3.1 Info and Relationships; 2.4.1 Bypass Blocks; 2.4.6 Headings and Labels
- **Recommendation:** Render the sidebar as `<nav aria-label="Primary">`, the screen viewport as `<main>`, and the Render Queue title as `<h1>`.
- **Suggested command:** `$impeccable polish`

### [P2] Destructive and system feedback bypasses the app dialog pattern

- **Location:** seven `window.confirm`/`window.alert` calls in `Download.tsx`, `RenderQueue.tsx`, `Profiles.tsx`, and `LayersPanel.tsx`; `TalkingVideo.tsx` confirm dialog.
- **Category:** Accessibility / Implementation Integrity
- **Impact:** Blocking native prompts interrupt the connected workflow and cannot present consistent consequences/recovery. The Talking Video dialog focuses Cancel but does not trap or restore focus.
- **WCAG:** 2.4.3 Focus Order; 3.3.6 Error Prevention
- **Recommendation:** Use one accessible confirmation dialog with labelled description, focus trap/restore, Escape, pending state, and inline success/error feedback.
- **Suggested command:** `$impeccable harden`

### [P2] Reduced-motion handling suppresses all feedback indiscriminately

- **Location:** `src/theme/global.css:575`.
- **Category:** Accessibility
- **Impact:** The global 0.01ms rule stops spinners, progress interpolation, and every other state-transition cue instead of supplying intentional non-motion alternatives.
- **WCAG:** 2.3.3 Animation from Interactions (best-practice handling)
- **Recommendation:** Keep scroll non-animated, disable decorative loops/transforms selectively, and retain textual/status feedback for loading and progress.
- **Suggested command:** `$impeccable adapt`

### [P2] Semantic theme tokens are not the implementation default

- **Location:** renderer-wide; strongest concentration in `Download.tsx` (85 hex-bearing lines) and `RenderQueue.tsx` (77).
- **Category:** Theming / Implementation Integrity
- **Impact:** Accent switching and future contrast corrections cannot update the whole product consistently; visually equivalent controls diverge by screen.
- **Evidence:** 440 JSX/CSS lines contain raw hex values, 47 of them in the token definition itself, leaving 393 outside the token source of truth.
- **Recommendation:** Migrate recurring surfaces, text, borders, status colors, radii, and spacing to the existing semantic tokens; leave media gradients and renderer-output styles local when genuinely content-specific.
- **Suggested command:** `$impeccable colorize`

### [P2] Most visual progress meters omit progress semantics

- **Location:** Sidebar, Render Queue, Talking Video, and older automation meters; only the shared Video Studio meter and automation step meter expose `role="progressbar"`.
- **Category:** Accessibility
- **Impact:** Screen readers receive nearby percentages inconsistently and cannot identify the value as changing task progress.
- **WCAG:** 4.1.2 Name, Role, Value; 4.1.3 Status Messages
- **Recommendation:** Add labelled `progressbar` semantics with min/max/value to determinate meters and `role="status"` text to indeterminate operations.
- **Suggested command:** `$impeccable harden`

### [P3] Repeated local thumbnails load eagerly

- **Location:** render, publish, talking-video, automation-library, and thumbnail-template lists.
- **Category:** Performance
- **Impact:** Larger local libraries decode off-screen images earlier than necessary, increasing initial screen work.
- **Evidence:** Only two of 21 JSX image sites explicitly request lazy loading; lists are bounded today, so impact is limited.
- **Recommendation:** Add `loading="lazy"` and `decoding="async"` to off-screen/list thumbnails; keep the current hero/preview image eager.
- **Suggested command:** `$impeccable optimize`

## Patterns & Systemic Issues

- The visual hierarchy depends too heavily on sub-AA gray rather than typographic hierarchy.
- The shared design system is mature, but legacy inline styling and native prompts bypass it in the two densest workflow screens.
- Keyboard and ARIA quality is otherwise strong: all tested form fields were labelled, visible images had alt attributes, tabs/switches exposed their state, dialogs were labelled, and no keyboard trap was observed in the newly hardened onboarding/template dialogs.

## Positive Findings
