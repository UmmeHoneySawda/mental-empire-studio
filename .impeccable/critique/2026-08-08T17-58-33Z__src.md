## Design Specificity Verdict

**LLM assessment:** The dark creator-studio language, live job status, pipeline cards, and media controls feel authored for Mental Empire Studio. Specificity falls away in the shell: twelve peer destinations are arranged as feature buckets, the title bar contains a generic avatar and decorative search control, and Automations reads like a separate marketing dashboard rather than the next stage of one production workflow.

**Deterministic scan:** The detector returned 13 warnings across six files: nine width transitions, two editor side accents, and two caption-font warnings. All nine transitions are determinate progress/status fills; the fonts are user-selectable burned-caption assets; and the side accents carry editor state. These are false positives or low-confidence style notes, not priority UX defects. The detector did not identify the higher-impact information-architecture, contradictory-state, and terminology failures found manually.

**Visual overlays:** No reliable user-visible overlay is available. Browser mutation preflight succeeded, but the external detector script failed to load. Rendered DOM inspection and computed layout measurements across Home, Sources, Compose, Settings, and Automations provide the browser fallback evidence.

## Overall Impression

The app has a strong production-software foundation and an unusually useful Home screen, but its shell still asks users to understand the implementation before they can understand the journey. The single biggest opportunity is to make every destination and state read as the next part of one video-production loop.

## What's Working

- Home’s “Needs you,” Resume action, pipeline stages, and useful empty states translate system data into next actions.
- Shared dark tokens, type families, status colors, and reusable primitives create a credible professional foundation.
- Background-state visibility is strong: active renders, auto-watch, source freshness, queue counts, and onboarding progress appear without opening logs.

## Priority Issues

### [P1] The shell describes features, not the production journey

**Why it matters:** Users must mentally translate Sources, My Channels, Compose, Talking Video, B-roll Pools, Automations, and output screens into a sequence. That creates working-memory load at every transition.

**Fix:** Reframe primary navigation around Today, Sources, Studio, Thumbnails, Render, and Publish. Keep Channels, media libraries, automation, and Settings visible but clearly secondary. Preserve every destination.

**Suggested command:** `$impeccable distill`

### [P1] Common desktop widths hide navigation labels

**Why it matters:** At the measured 1280×720 viewport the sidebar is 76px wide, turning twelve destinations into an icon-memory test and weakening current-location cues.

**Fix:** Keep the labeled rail through ordinary desktop widths. Use a deliberate compact mode only when the editor canvas truly needs it, with reliable tooltips and an explicit toggle if necessary.

**Suggested command:** `$impeccable adapt`

### [P1] Automations presents a contradictory impossible state

**Why it matters:** “Supervisor Active,” five “Ready” placeholder jobs, “0 unpublished available,” and a disabled launch action appear together. Users cannot tell whether setup is complete, broken, or merely empty.

**Fix:** Gate later steps behind prerequisites, surface the one blocking repair action, and reveal count/template/execution details only when source linkage and available videos make them valid.

**Suggested command:** `$impeccable harden`

### [P1] Global shell controls misrepresent behavior

**Why it matters:** The visible search field and ⌘K affordance do not search, and “Render all” sometimes only navigates to the queue. False affordances erode trust in the rest of the controls.

**Fix:** Remove decorative controls or make them honest. Use “Open render queue” when no ready queue can be executed; reserve “Render all” for a valid batch action.

**Suggested command:** `$impeccable clarify`

### [P2] Terminology and hierarchy vary by screen

**Why it matters:** “Configure,” “Step 02 — Compose,” “AUTOMATION ENGINE,” “visual system,” and “manual runs stage for edit” feel like different products and expose implementation vocabulary.

**Fix:** Establish one outcome-led vocabulary and page/section hierarchy, then apply it across the shell and high-traffic screens.

**Suggested command:** `$impeccable typeset`

## Persona Red Flags

**Alex (Power User):** The fake command shortcut wastes trust. Cross-stage work requires sidebar detours, and global batch/status actions do not consistently expose accelerators or preserve project context.

**Jordan (First-Timer):** The collapsed rail hides labels. “Owned channel” versus “source,” “visual system,” “rotation,” and engine/provider language require prior knowledge. Automations shows an impossible ready state without a single repair action.

**Sam (Keyboard/Screen-reader User):** Navigation is rendered as clickable `div` elements through helper semantics instead of native controls. Window controls are 12px targets. Collapsed labels and color-coded status carry important meaning, and the onboarding dialog shows no focus-trap/Escape handling in its implementation.

## Minor Observations

- “Auto-scrape” on Home is maintenance work, not the most valuable persistent secondary action.
- Settings is sensibly categorized, but seven peer tabs and a permanent Danger Zone tab deserve secondary grouping.
- The generic “A” avatar and version/status decorations consume shell attention without enabling an identity task.
- The browser mock logs a missing `visualTemplates.list` bridge during initialization; the UI recovers, but the fixture should be completed during hardening.

## Questions to Consider

- What if the shell always answered three questions: where am I, what is this video’s state, and what should I do next?
- Which concepts belong to the production path, and which are supporting libraries or configuration?
- What would Automations show if it were allowed to present only the current blocker instead of the future form?
